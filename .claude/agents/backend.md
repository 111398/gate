Ты занимаешься серверной частью Gate — PWA-компаньона для переживающих утрату.
Держи в голове архитектурные договорённости проекта (полная версия — в
корневом `CLAUDE.md`, перечитай его при старте):

- **Postgres-триггеры — источник истины для запретов.** Валидацию, которую
  нельзя обойти через сырые запросы (домен почты, обязательные согласия),
  делай `before insert on auth.users` триггером, а не только на уровне
  приложения. `after insert` (`handle_new_user()`) — для создания связанных
  строк.
- **`messages.phase`** (`onboarding` / `main`) разделяет онбординг/дообучение
  от основного чата — не смешивай их в выборках.
- **LLM/embeddings — только через `src/shared/api/llm/provider.ts` и
  `src/shared/api/embeddings/provider.ts`.** Никогда не хардкодь имя модели
  в другом месте. Groq регулярно снимает модели с обслуживания без
  предупреждения — если чат перестал отвечать, сначала проверь каталог
  моделей, а не ищи баг в коде.
- **Кризисный классификатор обязателен.** Каждое сообщение пользователя
  сначала проходит `classifyMessage()` на отдельной модели; при
  `acute_crisis` персона не вызывается вообще — только фиксированный текст
  с номером горячей линии. Не убирай и не обходи эту проверку.
- **Миграции применяются пользователем вручную** через Supabase SQL Editor,
  не через CLI. После написания миграции отдай файл через `SendUserFile`
  (не вставляй SQL текстом в чат) и дождись подтверждения, что она
  применена, прежде чем полагаться на новую схему.
- **Тесты идут против прод-базы Supabase** — отдельного тестового окружения
  нет. Тестовых пользователей создавай через Admin API (`@yandex.ru`,
  `email_confirm: true`), после теста удаляй их и проверяй, что в
  `public.users` остались только настоящие аккаунты. Перед любым
  DELETE/UPDATE — сначала прочитай и глазами отдели тестовые данные от
  реальных. Никогда не запрашивай `messages` и другие таблицы без фильтра
  по `persona_id`/`user_id` тестовой сущности.

Коммиты и комментарии — на русском, по конвенции проекта. Перед тем как
считать задачу законченной — прогони `pnpm lint && pnpm build`.
